# AGENTS.md

## Mission

Maintain SoundLab as a notebook-first, quality-first audio workbench.

The current interactive product is `notebooks/soundlab_studio.ipynb`; `soundlab.ipynb` is a legacy entrypoint pending consolidation. Reusable behavior belongs in `packages/soundlab/src/soundlab/`. The migration target is one generated root notebook backed by that package.

## Source ownership

- `packages/soundlab/src/soundlab/`: canonical reusable Python behavior.
- `notebooks/soundlab_studio.ipynb`: current interactive Colab entrypoint.
- `soundlab.ipynb`: legacy entrypoint; preserve until parity is verified.
- `tests/`: package, notebook, integration, and failure-path checks.
- `docs/`: current architecture, runbooks, model/license notes, and evidence scope.
- `agents` repository: generic harness, MCP, and skill infrastructure.
- `dotfiles` repository: machine-level tooling and desired state.

Do not duplicate cross-project agent infrastructure or user machine configuration here.

## Tooling

Use `uv` as the Python resolver and the repository's existing task conventions. Do not introduce another task runner or framework without a concrete unmet requirement.

The repository does not currently contain a reviewed `uv.lock`; do not use or claim frozen dependency resolution until a lock is generated by `uv`, installed in a clean environment, and committed.

## Product invariants

1. Every supplied input remains represented in the final batch, including failed, blocked, partial, and cancelled inputs.
2. Original source bytes are never silently modified.
3. No silent normalization, mastering, denoising, resampling, downmixing, quantization, or clipping.
4. Continuous full-track estimates precede section cropping where context matters.
5. Candidate comparison requires compatible target, sample grid, timing, polarity, channel orientation, and gain convention.
6. No-reference residual or correlation metrics are not SDR or perceptual truth.
7. Human edits retain source identity and the original model proposal.
8. Disabled operations contribute no validation requirements.
9. `READY` means the selected backend is installed/importable, accessible, acknowledged, and resource-admissible.
10. Secrets are referenced by name and never printed, placed in ordinary forms, committed, or exported.
11. Drive, public sharing, hosted uploads, paid services, model inference, and destructive cleanup are explicit opt-ins.
12. Results bind source identity, reviewed settings, code/model identity, and artifact hashes.
13. A local timeout does not prove remote cancellation.
14. Package/archive validation is not a claim of musical correctness.

## Notebook contract

The notebook must:

- remain useful as a standalone Colab entrypoint;
- use safe sample defaults;
- avoid authentication and external services in sample mode;
- validate the actual runtime instead of promising a GPU;
- stop clearly at required restart barriers;
- define Gradio without launching it automatically;
- provide a native fallback when the web UI cannot launch;
- clear outputs, execution counts, attachments, widget state, secrets, and private paths before publication;
- pass `nbformat.validate()` and source/notebook identity checks.

Until deterministic notebook generation is implemented, any notebook edit must include explicit parity checks against the package and the other entrypoint. Do not delete either primary notebook without a reviewed migration.

## Dependency and publication policy

- Preserve the existing compatible stack unless evidence requires a change.
- Use explicit core and optional-backend dependency groups.
- Treat backend compatibility separately from core compatibility.
- Never downgrade the whole runtime silently for one optional backend.
- Do not install the unrelated PyPI project named `soundlab`.
- Do not publish this project to PyPI until an available distribution name and publishing policy are selected.
- Build artifacts may be tested locally or in CI without publication.
- Do not blindly upgrade Torch or CUDA packages in Colab.

## UI/UX policy

The user works on a song, not a pipeline configuration.

- One selected asset across all surfaces.
- One shared transport/playhead.
- Contextual operation controls.
- Advanced model internals available but collapsed.
- Draft, applied, running, stale, partial, failed, and complete states visibly distinct.
- Non-drag alternatives, keyboard/focus support, reduced motion, and mobile layouts.
- Concise, actionable prose.
- Do not measure UX quality by control count or HTML element count.

## Testing and evidence

Run inherited tests plus regressions for every repaired defect. Never weaken tests to obtain a pass.

Keep evidence classes separate:

- static/schema;
- local runtime;
- synthetic integration;
- browser/component rendering;
- managed Colab;
- external service;
- perceptual/human review;
- package/release reconstruction.

A PASS must name the exact subject and environment. GitHub Actions is not managed-Colab evidence. CI uses synthetic/public fixtures and least-privilege permissions; do not place Colab, Drive, model-service, or private-data secrets in ordinary CI.

## Git and releases

- Preserve history and unrelated edits.
- Use Conventional Commits.
- Prefer focused branches and PRs; direct `main` writes require explicit user approval.
- Re-read the base before publication.
- Do not tag, release, enable publication, change repository settings, or publish packages without explicit approval.
- Do not claim a release from a commit message alone.
- Release exact notebook/package bytes with manifests and hashes.
- Model licenses and service terms remain separate from the MIT code license.

## Documentation

Keep durable policy here. Do not append session logs, temporary claims, or historical validation transcripts to `AGENTS.md`.

Use issues and PRs for work state, `CHANGELOG.md` for user-visible changes, and bounded evidence artifacts for test receipts.

## Definition of done

A change is done only when:

- source and affected notebooks agree or explicitly document a migration gap;
- relevant tests pass without weakened gates;
- runtime and external-service gaps are explicit;
- no secret, private data, output, or model-weight leakage is found;
- README and docs match actual behavior;
- exact changed artifacts are reviewed and hashed;
- unrelated work is preserved.
